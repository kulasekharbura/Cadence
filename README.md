# AI-Powered Document Q&A System

This project is a modern, containerized, full-stack application designed to perform grounded Retrieval-Augmented Generation (RAG) over uploaded PDF documents. It relies on a custom, transparent RAG pipeline that explicitly bypasses heavy orchestrators (like LangChain or LlamaIndex) in favor of direct, verifiable integration with Google's Gemini models and PostgreSQL's `pgvector`.

## Features
- **Strictly Scoped Conversations**: Conversations are explicitly bound to specific documents. The system cannot leak context across conversations.
- **Deterministic Custom Chunking**: Uses a custom word-boundary sliding-window chunking strategy bounded strictly to individual PDF pages (No cross-page chunks).
- **OCR Fallback**: PyMuPDF OCR (Tesseract-backed) is seamlessly invoked for scanned/image-only pages. Normal text extraction is attempted first, ensuring maximum speed and accuracy where possible.
- **Markdown UI**: Gemini responses are rendered as clean, professional Markdown in the chat UI, preserving bold, lists, and tables.
- **Grounded Citations**: Extracted answers provide precise `[Source N]` markers. The backend explicitly validates these markers against the retrieved context and persists exact chunk-mappings to the database. The frontend renders these as interactive, verifiable chips (`filename.pdf · p.X`) pointing to the raw extracted source chunk.

## Technology Stack
- **Frontend**: React 19, TypeScript, Vite, TailwindCSS, TanStack Query, React Markdown.
- **Backend**: Python 3.11, FastAPI, SQLAlchemy (async), asyncpg, Alembic, PyMuPDF, Tesseract OCR.
- **AI Integration**: `google-genai` SDK using exclusively Google Gemini models.
  - *Embedding*: `gemini-embedding-001` (1536 dimensions, batched up to 100 requests per API call)
  - *Generation*: `gemini-3.5-flash` (Primary), `gemini-3.5-flash-lite` & `gemini-3.7-flash` (Fallbacks)
- **Database**: PostgreSQL with `pgvector`

## Getting Started

### Prerequisites
- Docker and Docker Compose (Tesseract OCR dependency is baked into the backend Docker image)
- A valid Google Gemini API Key.

### Installation & Setup

Follow these exact steps for a fresh clone:

1. **Clone repository**
2. **Create `.env` from `.env.example`**:
   ```bash
   cp .env.example .env
   ```
3. **Set `GEMINI_API_KEY`**:
   Open the `.env` file and insert your active API key:
   ```
   GEMINI_API_KEY=your_gemini_api_key_here
   ```
   **SECURITY WARNING**: The `.env` file and the `GEMINI_API_KEY` must **never** be committed to source control.
4. **Start Docker Compose**:
   ```bash
   docker-compose up --build -d
   ```
   *Note: `docker-compose up --build` does NOT automatically apply database migrations.*
5. **Apply Alembic migrations**:
   ```bash
   docker-compose exec backend alembic upgrade head
   ```
6. **Verify backend health**:
   Check that the FastAPI application is healthy by navigating to `http://localhost:8000/api/v1/health`.
7. **Open frontend**:
   Navigate your browser to `http://localhost:5173`.

## Database Setup and Migrations

This application uses **PostgreSQL + pgvector** as the database. **SQLAlchemy** is the ORM/database access layer, and **Alembic** manages database schema migrations.

A fresh database does NOT automatically have the application tables. You must manually apply migrations. The current application schema includes the existing `documents`, `document_chunks`, `conversations`, `messages`, `conversation_documents`, and `message_sources` tables.

After starting Docker Compose, you must run:
```bash
docker-compose exec backend alembic upgrade head
```

### Useful Alembic Commands

- View current revision:
  ```bash
  docker-compose exec backend alembic current
  ```
- View migration history:
  ```bash
  docker-compose exec backend alembic history
  ```
- Autogenerate a new migration after changing SQLAlchemy models:
  ```bash
  docker-compose exec backend alembic revision --autogenerate -m "description"
  ```
  *(Important: Always review autogenerated migrations before applying them to ensure correctness.)*
- Revert the last applied migration:
  ```bash
  docker-compose exec backend alembic downgrade -1
  ```

## Important Security & Version Control Exclusions

The following resources are explicitly excluded from source control and must remain local to your development environment:
- `.env` files containing sensitive credentials.
- The `GEMINI_API_KEY` (must never be committed).
- `node_modules/` (Frontend dependencies).
- `__pycache__/` and `.pytest_cache/` (Python caches).
- Uploaded runtime PDFs (e.g. `backend/uploads/` directory).
- Local or generated IDE artifacts.

## Core API Endpoints

The backend exposes a RESTful API. Below are the most critical endpoints for application operation:

- **Upload Document** (`POST /api/v1/documents/upload`)
  - Accepts `multipart/form-data`. Uploads, chunks, embeds, and stores a PDF.

- **Delete Document** (`DELETE /api/v1/documents/{document_id}`)
  - Deleting a document cascades deletion of the document, its vector chunks, and its associations with conversations. Existing conversations remain intact.

- **Create Conversation** (`POST /api/v1/conversations`)
  - Accepts a JSON array of `document_ids`. Explicitly isolates the chat context to those files.

- **Chat** (`POST /api/v1/chat`)
  - Accepts `conversation_id` and the user's `message`. Returns the LLM `answer` alongside validated `sources`.

- **Conversation History** (`GET /api/v1/conversations/{conversation_id}`)
  - Returns the entire chat history, including eagerly loaded per-message citations.

- **Delete Conversation** (`DELETE /api/v1/conversations/{conversation_id}`)
  - Cascades deletions of all messages and mapping data.

- **Source Inspection** (`GET /api/v1/sources/{chunk_id}`)
  - Fetches the raw text, page number, and filename for an exact database chunk to populate the frontend source details panel.
